## Native ownership and API

All eight new production native files are in `engine/ardiacore-linux/src/ardia/linux/`.

`LinuxPageMountAuthority(browser, weakWindowWidget, contents, shell, identity)` captures the original weak `BrowserWindowInterface`, `Profile`, page and shell `WebContents`, weak host-window `views::Widget`, original browser-window identity and shell committed `WeakDocumentPtr`. `LinuxPageIdentity` has `native_id`, application `key`, `claim`, `renderer_generation`, `binding_generation`, `native_generation` and `handler_identity`. The latter generations/identity must be nonzero and immutable for that mount. Browser-window identity is compared only after the weak browser/profile/window/page/shell authorities pass. Membership is checked in the captured browser's tab strip; the helper never looks through global windows or IDs for a replacement owner.

The authority belongs to the original mount. `Invalidate()` must precede owner retirement, any mutation of ownership fields and teardown. Recreating an authority with the same values cannot revive old weak references. Its weak widget provides an additional original-window lifetime check; the captured `ui::BaseWindow*` is identity only and is never dereferenced.

`LinuxPageLease(weakAuthority, sink, requestSnapshot)` observes the original page. Its APIs are:

- `Capture() -> optional<LinuxPageRequest>` for document work, plus `request.Valid()` and `lease.Valid(request)`.
- `CapturePresentation() -> optional<LinuxPageRequest>` for an authoritative snapshot, including a cleared presentation while provisional navigation is pending.
- `contents()` for validated, nonsuppressed document reads; `observed_contents()` only for attaching observers to the original contents during a provisional mount.
- `Emit(request, name, data)`, `EmitSnapshot(request, orderedEvents)`, `CreationState(request, orderedEvents)`.
- `CancelDocumentWork()` and terminal `Reset()`.

A request captures the original lease weak pointer, primary-page `WeakDocumentPtr`, document epoch and request generation. Validation requires the original authority and browser membership, the exact current primary document and matching epoch/request generation. An old BFCache document remaining alive is insufficient. Ordinary page results are suppressed during provisional navigation. Presentation snapshots can still contain the cleared state, using a presentation capture made for that generation. Never retain only a weak lease and recapture inside an asynchronous completion: retain its original request and validate it at completion.

The sink signature is `void(std::string module, std::string id, base::DictValue payload)`. Bind it to the original weak host/handler and validate that captured handler/generation when entering the host's event channel. Do not bind a raw host or post a later `Binding(id)` lookup. Snapshot-request signature is `void(LinuxPageRequest, std::string reason)`; reasons are `document` and `restore`. Bind the original weak binding. Gather snapshots synchronously or retain this request through any asynchronous work and pass it unchanged to `EmitSnapshot`.

`LinuxSecurity(weakLease)` provides `Snapshot() -> DictValue`, `Emit()`, `Reset()`, visible-security observation and destruction detach. `Snapshot()` returns the package's complete required security fields (`level`, `url`, `origin`) and available optional details. It checks a visible, noninitial entry before calling `security_state::GetVisibleSecurityState`, and requires initialized connection data before HTTPS conclusions. HTTP is insecure; only recognized internal/file schemes are local. Certificate errors take precedence over mixed state, active mixed content over displayed mixed content; a missing certificate stays unknown. Revocation-check-unavailable bits are excluded consistently with the Mac mapping. Certificate principals, Unix milliseconds, chain length, serial, SHA-256, protocol and mapped errors are included when available. No certificate PEM, client certificates, cookies, secrets or paths are exported.

`LinuxHistoryZoom(weakLease)` provides `GoToOffset(args)`, `ZoomStep(args)`, optional `Snapshot()`, `Emit()`, `Reset()` and observers. Both commands return `false` for malformed arguments or unavailable authority, allowing the dispatcher to reject. A valid offset of zero and a valid offset outside available history return `true` without navigation. Exactly one finite integral native-int argument is required. `CanGoToOffset` precedes navigation. `ZoomStep` accepts only -1/0/1 and uses `zoom::PageZoom::Zoom`, including the actual default reset. Zoom snapshots report a factor, host, native default status and separate pinch scale. Zoom-controller destruction explicitly deregisters the observer; reset does the same before releasing state.

A nonunit pinch scale at initial/rebind snapshot is queried from the primary contents' native widget render-frame metadata. Subsequent scale observations carry their document request so an old-document cache is not reused after a boundary. The private `RenderWidgetHostImpl` include has the allowed `nogncheck` directive. This is a narrow pinned-source dependency and still needs the joined GN/link/runtime check. Do **not** add a direct `//content/browser` dependency: that target's visibility excludes this target. The existing public content dependency links its implementation. If embedder DEPS checking forbids this include at integration, resolve that specific policy seam; do not substitute a fabricated pinch scale.

`LinuxTheme(weakLease, navigationSnapshot)` provides `Snapshot()`, `Emit()`, `Reset()` and native theme observation. The callback must return the original binding's complete public navigation snapshot and must use a weak original binding. The helper checks its own weak lifetime and the captured request after calling it. `Snapshot()` contains just `themeColor` and `themeColorSource`; merge it into every complete navigation snapshot. Native meta color becomes lowercase `#rrggbb` with source `meta`; absence/suppression is explicit null/null. No background fallback or fabricated header provenance is supplied.

2. Store authority, lease, security, history/zoom and theme helpers per native mount. Mint a new nonzero binding generation for each claim/reclaim/rebind/transfer attachment, even if the string claim is reused; never reuse the predecessor's binding generation. Keep sequence monotonic within that binding incarnation. Construct only after native tab helpers/zoom controller and original browser membership are installed.
3. Before release/reclaim/transfer/rebind, renderer loss, shell retirement, contents destruction or host/window destruction: reset lease sinks/request callbacks first, invalidate authority, reset/detach helpers and cancel retained requests/actions before changing/releasing the owner. Invalidate before removing original tab-strip membership or clearing handler generation. Subsequent callbacks must not search for today's owner. The host's existing `TabBinding` observer must also obey this ordering before its terminal events.
4. The lease itself observes `PrimaryPageChanged`, provisional primary cross-document starts, matching abort completion and destruction. Do not call the primary boundary twice. Primary-page changes advance the document epoch and invalidate requests before emitting a reset, then invoke `requestSnapshot` with the new capture. Same-document navigation does not advance epoch. BFCache restores create a new reporting epoch and snapshot. A provisional start advances only request generation, immediately clears presentation and suppresses document results; cancellation requests a snapshot of the still-primary document without a permanent new epoch. An already-pending navigation at mount is detected via `GetPendingEntry`; observers still attach, while initial presentation is clear. Do not turn `DidStartLoading` or a URL change into another document boundary.
5. Compose ordered snapshot events with full `navigation` (including the theme helper's nullable fields), `security`, available `zoom`, then queried actual fullscreen/crash/status and later popup/recovery state. Snapshot application resets before replay. Later popup snapshots must replace existing popup state before replaying entries, rather than appending on top of reclaim state. Do not invent missing runtime state. Renderer/hung/popup producers remain with their later owner.
6. `tab.create` must preserve **all existing response fields**, adding only `CreationState`'s `{lease, snapshot: {watermark, events}}`. Use one captured presentation request while gathering the ordered events. Failure because that request expired requires a fresh authoritative snapshot/creation response, not an old response mislabeled with a new epoch. The helper reserves the snapshot watermark in the same sequence stream as emitted events.
7. Remove the posted ID-only `CreateTab` navigation report and every later posted `Binding(id)` reporting lookup in the integrated path. Convert owned page events to the envelope below and route through the captured lease. Do not send both old navigation/title events and a complete new navigation event. Convert legacy title updates into one complete navigation snapshot with nullable theme fields. Preserve existing PiP and other supported public events through the same validated delivery, or explicitly coordinate their producers with their owners.
8. Register disjoint tab-command branches: `getSecurityInfo` requires zero arguments and returns the security snapshot; `goToOffset` delegates its argument list; replace the existing `zoomStep` body with the history/zoom helper. Keep F01 find/commands/DevTools registrations separate. A command response must revalidate its original captured request before native completion, and the JS command fence below must still pass when its awaited response is consumed.
9. For domain calls, intercept only `sites.zoomLevels` / `sites.setZoom` before the generic route table. Parse the existing public argument JSON object and call `PrepareLinuxZoomDomain(method, args)`. Invalid supported calls reject using the existing engine error model. Resolve the supported original profile through the existing native domain gate, then dispatch the returned service and argument dictionary through the existing C-service dispatcher. On a successful native service result, call `CompleteLinuxZoomDomain(method, reply)`; reject a malformed result and preserve real service errors. `sites.zoomLevels` invokes `ac_zoom_list`, extracts `levels`, converts logarithmic levels to factors rounded to two decimals and returns the factor dictionary. `sites.setZoom({host,zoom})` invokes `ac_zoom_set({host,level})` and returns public null. The adapter rejects `tab` overrides, unknown/extra fields, credentials, paths, ports, malformed/unbounded hosts, and nonfinite/nonpositive factors. The native service's zero-level convention remains its existing default-zoom behavior.

## Wire and Linux UI integration

Outer channel remains `module = "ArdiaWebView"`, `id = String(originalNativeId)`. Every envelope has `claim`, decimal-string `rendererGeneration`, `bindingGeneration`, `documentEpoch`, plus a strictly increasing safe-integer `sequence`. The native helper stops delivery and invalidates requests rather than overflowing 9,007,199,254,740,991. Epoch/request counters likewise fail closed on uint64 overflow.

- Ordinary events: `{type: "pageEvent", event: {name, data}, ...metadata}`. These retain the exact package names and payloads, including `find`, `focus`, scalar fullscreen/status callback unwrapping and two-argument page messages.
- Reset control: `{type: "pageLifecycle", action: "reset", reason: "document" | "provisional", ...metadata}`.
- Authoritative snapshot control: `{type: "pageLifecycle", action: "snapshot", events: [{name,data}, ...], ...metadata}`.
- Create response addition: `{lease: metadata, snapshot: {watermark, events}}`; the lease may also have private `type`/`sequence` fields. Existing creation fields remain authoritative for the outer numeric channel.

`HostPageEvents(claim, nativeIdGetter, propsGetter, resetCallback, applyThemeCallback)` is the new production transport consumer. Create it before native create starts; feed its `receive(module,id,payload)` directly from the native listener. Install create identity first, then call `install(createResponse)` once. It copies and bounds early events to 128, sorts them, applies the response snapshot once and replays only exact matching-binding events newer than its watermark. A pre-response newer reset/snapshot wins in sequence order; buffered old epochs cannot undo it. Early overflow closes the receiver. Reentrant delivery is queued behind the whole current reset/snapshot with bounded draining, and disposal halts replay.

Ordinary events cannot self-adopt another epoch. Only an exact matching claim/binding/shell-generation authenticated reset or authoritative snapshot may advance it; old epochs and nonincreasing sequences are rejected. Provisional reset has to keep the current epoch. It also suppresses stale security/popup/page-message presentation and nulls navigation theme data until restoration/new-document control.

Pass callbacks `(reason) => resetHostPage(tabId, reason)` and `(state) => applyHostPageTheme(tabId, state)`. These call existing shared `patchPage`, `setPopover`, `updateLive` and `revealToolbar` actions. There is no additional page store. Reset clears certificate/security, theme provenance/color, popups, status, crash/hung/fullscreen and relevant prompts before navigation/snapshot callbacks. Shared `restoredThemeColor` can otherwise reintroduce a saved tint on same-URL navigation: `applyHostPageTheme` runs **after** shared navigation dispatch to make native explicit null and meta provenance authoritative. Both URL and committed-URL translation remain in the Linux event adapter before the actual shared `deliverPageEvent`.

For a command, call `captureRequest()` after ready and immediately before invoking native. Hold the returned predicate over the await; it must still return true before consuming a result. A null capture means provisional/uninstalled/disposed authority and must refuse the command. Document/reset/snapshot/provisional/disposal invalidates older predicates, including same-epoch abort restoration. Replace the old `HostWebView` callback routing table with this consumer and the real package dispatcher; do not add a parallel public WebView API. Clear the receiver on replacement/unmount before sending release. Same-claim rebind creates and installs a fresh receiver/binding snapshot.

The component alias is reserved for the integrator: add the resolved path `apps/browser/src/components/site/SiteConnection.tsx -> apps/linux/src/SiteConnection.tsx` to Linux's existing Vite replacement map **and adapter exclusion set**. This lets the wrapper import the original without recursion. The wrapper exports `ConnectionChip`, `ConnectionRow` and the original `CertificateDetails`. Unknown/null is “Connection information unavailable”; known states and details use the shared component. The graph fixture temporarily supplies exactly this alias and proves real `SiteControls` reaches the wrapper, with the original imported only by that wrapper. It does not alter Vite or register the alias in this branch.

Remaining cross-owner UI work includes guarding earlier shared popup-prompt promises before they can reopen popovers after reset, and any pending site-panel `getSecurityInfo` result must go through the command predicate. Popup/recovery handling is not implemented here. Keep native and JS command-fence checks when those owners add asynchronous work.
