This implements the assigned helper, shared seam and renderer close-barrier source for #14. It does not close F04 or establish Chromium 156 runtime acceptance. Work is based on planning d4df45f7 plus separately cherry-picked dependencies ending at local 8fa97a40. No demo source, owner data or Chromium checkout/output is modified.

## Canonical authority

`LinuxDocuments` in `ac_linux_documents.h` is owned by the native storage service, independent of renderer weak reply callbacks. Construct exactly one instance per actual supported regular native profile. Every call, including destruction and subscription removal, runs on the same existing sequenced BLOCK_SHUTDOWN FileRunner. Resolve storage path, regular-profile permission, native scope and native renderer incarnation on the UI sequence before posting work. Unsupported private/isolated profiles and ordinary pages fail closed. Payload `profileId` is logical metadata and grants no authority.

The constructor takes native scope, a fresh native epoch, a bounded read callback and an atomic persistence callback. Reads return `LinuxDocumentRead` with distinct missing/found/error states. Read only `live.canonical.json` and, once during envelope initialization, legacy `live.json`. The persistence callback serializes the entire envelope to `live.canonical.json` through the host's existing safe atomic document writer. Never split payload and metadata into separately authoritative files. A storage callback failure must be reported as false, never successful caching. Current Chromium atomic replacement still needs real crash/power-loss qualification; these fixtures do not establish that guarantee.

`Watch(client, changed)` registers before the ordered initial read. `Commit(client, request)` rereads current storage, validates preconditions, applies to a temporary envelope and persists before source acknowledgment or peer fanout. `Flush(client, request)` rereads durable storage and verifies the caller's own accepted watermark. `Unwatch(client)` removes only that native client and releases its refresh ownership. Accepted worker requests and peer fanout must survive source renderer destruction. UI delivery callbacks must recheck target scope, subscription and renderer incarnation.

`LinuxDocumentClient` is a trusted native value containing native-minted `id`, native `scope`, and resolved privileged/regular permissions. It is never deserialized from renderer arguments. The host must authenticate the actual native profile rather than authorize via a requested profile string or fall back to default storage.

The envelope retains Live payload version 1 separately from `format`, `epoch` and `revision`; it also stores incarnation/tombstone/generation/owner maps and per-client last accepted request receipts. Legacy version 0 migrates unchanged with existing option/config/calendar defaults. Invalid/newer legacy payloads become defaults on the first canonical save, matching the shared saved-document fallback. Malformed canonical envelopes fail closed and never trigger legacy import. Canonical reset, if added later, must retain an envelope; deleting the envelope is not a reset API.

Requests are strictly serialized per native client with IDs `<native-client>:<sequence>`, starting at 1. The last accepted request's operations are retained for lost-reply retry; identity reuse with different operations rejects. Older expired request IDs reject instead of reapplying. Snapshot watermark initializes same-renderer reconnect sequencing. A fresh authority changes epoch while retaining accepted receipts; reconnect resnapshots and removes already accepted pending sequences. New renderer incarnations get new native clients.

Bounds are 64 subscriptions, 256 persisted client receipts, 2,048 operations per batch, 8 MiB serialized envelope/request, bounded depth/nodes and integer revisions/sequences. Exhaustion refuses further edits explicitly. Tombstones are not compacted: safe future compaction must rotate the epoch and invalidate older bases. There is no time-based resurrection window.

## Transport and operations

Route only `documents.watch`, `documents.commit`, `documents.flush`, and `documents.unwatch` through the current `ArdiaDocuments.call(verb, profile, JSONargs)` path. Return JSON text and reject `LinuxDocumentResult.code/message` through the structured bridge error model. Watch/unwatch accept exactly `{document:'live.json'}`; the host validates that shape before calling the helper. Commit accepts exactly `{document,epoch,requestId,observedRevision,operations}`. Flush accepts exactly `{document,epoch,watermark}`. No scope/path/client authorization fields come from JS.

Snapshots contain `{document:'live.json',scope,clientId,epoch,revision,watermark,payload,incarnations,generations}`. Commit returns `{status:'committed'|'conflict',snapshot,requestId,superseded?}`; conflicts include current canonical state. The changed callback receives `{snapshot,clientId:<source>,requestId}` with a personalized recipient snapshot. Emit module `ArdiaDocuments`, channel `documents`, envelope `{name:'documents.changed',data:<callback payload>}`. Send source renderers their own acknowledgments.

The Linux renderer registers its listener before watch, buffers loading events, applies monotonic revisions, resnapshots on reconnect and keeps canonical state separate from pending intent. The shared Live domain applies canonical projections under persistence suppression while preserving transient status/completing/showAll. Generic document reads project only acknowledged canonical Live payload, never pending edits. Failed writes retain dirty work and block flush. An explicit `discardPending` helper exists for unresolved user conflict recovery; accepted in-flight work cannot be discarded.

Operations are folder create/delete, existing-incarnation field patch, ordered identity placement, calendar/config field patch, per-ID memberships, items/hidden/completed entry mutations using actual item IDs, non-secret account/meeting metadata and expanded-stack values. Filter booleans are independent fields. Explicit placement intent never submits a stale folder-order snapshot. Refresh claims establish one native client owner per folder. Refresh batches carry generation/owner/incarnation and explicit ordered item identities; deletion, user item actions, filter/config/account changes and owner retirement fence late results. A stale refresh commits an explicit superseded no-op so it cannot block later user edits. Same-field user conflicts recondition the original narrow intent against current state; missing incarnations and ambiguous placement conflicts remain failures for explicit retry/discard, never implicit creation.

Account and item schemas allow only non-secret metadata fields. Credential keys are rejected rather than persisted, emitted or included in error text. Dedicated protected credential storage, opaque sealed sync files, unrelated documents and awaited `saveDocument` semantics are unchanged.

Reserve BOTH `live.json` and `live.canonical.json` from generic native reads/writes/removal and bootstrap enumeration with `LinuxDocuments::Reserved`. This host-side protection is mandatory even though the renderer adapter also refuses blind writes. The legacy reader/persistence callbacks are internal exceptions and must not call through a generic reserved-name rejection.

## Close contract and remaining integration

The owned shell installs its close listener before any request. Native emits `ArdiaShell` channel `shell`, envelope `{name:'shell.closeRequested',data:{windowId,rendererGeneration,closeGeneration}}`. Both generation values are native decimal strings and are passed through without numeric coercion. `requestWindowClose(id)` only requests the target renderer's barrier. `acknowledgeWindowClose({...request,watermark})` follows producer quiescence and session/document drain. `rejectWindowClose(request)` cancels the attempt and retains the window; only confirmed cancellation resumes producers.

Session and document quiescence are token-scoped. Repeated same-generation requests share one barrier promise. Canceling one token cannot resume another attempt. Session debounce is canceled before final drain; subsequent local producers are gated while canonical delivery remains active. The disposal-time `onBeforeClose` callback is best effort and submits no extra session write after an established barrier. A timeout never becomes successful closure.

On the FileRunner, `Seal(client, close_generation, watermark)` rereads storage, verifies exact own-client durable accepted sequence equality and seals later commits before returning success. Repeated matching seals are idempotent. `CancelSeal(client, close_generation)` unseals only the matching generation. Native host must independently validate window/renderer/close-generation ownership, seal session/other accepted routes as needed and only destroy the UI after this worker operation succeeds. No-document-client windows may skip the Live seal only when native ownership proves no accepted document work. Bare `closeWindow` must enter the request path and cannot acknowledge another renderer. Native compositor/keyboard/quit routes and lost-reply retry/idempotence remain the host integrator's responsibility.

F21 warning/confirmation integration remains separate and must preserve the shared warning flow. These helpers do not establish that warnings or every native close route work. F11/F14 consumer coding can use this interface, but their full acceptance remains blocked by F04 integration/runtime evidence.

They are not a native joined runtime, real profile isolation proof, compositor verification, power-loss durability proof or Chromium 156 API/GN qualification.
